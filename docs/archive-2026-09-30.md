## 恢复当前新服务器部署

下面是供以后恢复时使用的步骤，本次归档不执行这些操作。恢复前保留目标机器已有数据，准备具有 Docker Compose 的 Linux x86_64 主机，并只在受控目录解压私密备份。

1. 按最终归档校验记录核对两个新机备份包的 SHA-256。可用 `tar -tzf` 再确认目录结构；新机包为 `./` 顶层，不需要去掉路径层级。
2. 将 `cloud-current-20260930.tar.gz` 解压到权限为 `0700` 的暂存目录，再将暂存目录内的完整项目文件恢复到 `/opt/coolapk-docker`。保留备份中的 `.env` 与 `data/`，不要用 `.env.example` 覆盖实际部署配置。
3. 将镜像导出包加载到目标 Docker。以下示例假定备份包已复制到目标机的受控备份目录：

```bash
gzip -dc /secure-backup/cloud-image-20260930.tar.gz | docker load
docker image inspect coolapk-docker:local --format '{{.Id}}'
```

`docker load` 会恢复导出时的镜像标签。当前 Compose 使用 `coolapk-docker:local`；若加载包的标签不同，先根据归档镜像记录确认实际镜像，再为正确镜像添加该标签，不要随意引用其他项目镜像。

4. 恢复持久化目录权限。容器以 UID/GID `1000:1000` 运行，账号与设置文件必须允许该身份读写；部署配置仅允许部署用户读取。

```bash
cd /opt/coolapk-docker
sudo chown -R 1000:1000 data
sudo chmod 700 data
chmod 600 .env
docker compose config --quiet
docker compose up -d --no-build
docker compose ps
curl --fail --silent http://127.0.0.1:18966/healthz
```

保留数据子目录及文件原有私有权限，不要为方便写入而设置 `0777`。健康接口只证明服务启动；账号有效期、业务页面和媒体仍需分别检查。Cookie 持久化不会延长酷安官方会话有效期。

5. 若恢复到不同服务器，确认 `.env` 中的绑定地址、端口和公开 origin 与实际入口一致，并将 Lucky 的本项目规则指向恢复主机。恢复到当前主机时继续使用 `203.0.113.10:18966`，不要恢复为旧 NAS 地址。

新机资料包排除的缓存会在正常浏览时重新生成或下载。若需保留飞牛删除前全部资料，只在受控暂存目录解压 `fnos-complete-20260930.tar.gz`，其项目根目录位于暂存目录的 `coolapk-docker/`；不要把其旧配置或旧镜像迁移包直接覆盖当前新机部署。
